Set up `/today` as a running record of the work I actually finish each day. One markdown file per day, a GitHub Action that rebuilds an index, and a page on my own domain that reads both.

What I worked out before writing any code:

- `jagdishverma.com` is a Cloudflare Pages project called `jagdishverma`, uploaded directly from the Cinderworks build. No framework, no functions.
- Every unknown path on that domain returns the homepage, so `/today` needs a real file in the deploy rather than a redirect rule.
- GitHub Pages cannot take one path on a domain Cloudflare already serves. It only owns a repo root or its own subdomain, so the content lives on GitHub and the page stays on Cloudflare.
- Entries are `entries/YYYY-MM-DD.md` with frontmatter for the title and tags. A push to `entries/` rebuilds `index.json`, so the page never needs a redeploy to show new writing.
- The heatmap greens are graded against the longest entry, not fixed word counts. Every cell is recomputed on load, so a new longest entry re-grades the whole year.

The page itself fetches `index.json` from `raw.githubusercontent.com`, renders the selected day with marked and DOMPurify, and keeps everything inside the site's own warm dark palette. No build step, no token in the browser.
